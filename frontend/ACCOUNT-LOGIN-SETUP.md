# AI 教程小程序接入 52okp 登录中枢

本次新增扫码确认入口，教程文章、分类、收藏、历史和原有会员接口继续使用原系统。统一账号由 Keycloak 管理；教程会员与统一账号本次不迁移、不自动关联。

## 已新增

- 确认页：`pages/account-confirm/index`
- 账号说明页：`pages/account-policy/index`
- 独立接口封装：`src/common/account-login.js`
- 中枢地址：`https://open.52okp.com/realms/52okp/wechat`

用户扫描原网页生成的小程序码，进入确认页。页面查询申请应用和有效期；用户主动同意账号说明并点击确认后，才取得新的微信临时 code 并提交中枢。页面支持取消、过期、重复处理和错误提示。确认成功表示中枢已收到确认，最终登录或绑定结果以原网页显示为准。

扫码进入确认页时跳过 App 启动时的教程会员静默登录。正常从首页启动仍保留原行为。中枢请求不发送教程的 Member-Token，不接受二维码指定任意服务地址，不发送客户端声称的 OpenID 或用户 ID。AppSecret 只配置在服务端。

## 中枢后台填写

在「身份验证 → 流程 → 52okp 浏览器登录 → 扫码登录步骤 → 设置」填写：

| 项目 | 值 |
| --- | --- |
| 小程序 AppID | wx4ec45155a93041cc |
| 小程序 AppSecret | 从该小程序微信后台获取，仅填中枢后台 |
| 小程序登录页路径 | pages/account-confirm/index |
| 小程序版本 | 联调使用有新页面的体验版；发布后使用正式版 |

页面路径不带开头斜杠、不带 .vue 后缀、不追加 scene。中枢会将短期随机票据写入小程序码的 scene。

上传并设置体验版后再启用扫码。当前中枢生成小程序码使用 check_path=true；仅修改本地代码、尚未上传相应版本时，微信不能访问新增页面。

## 微信小程序后台填写

在该 AppID 对应的小程序后台添加 request 合法域名：

`https://open.52okp.com`

保留教程后端现有域名。核对中枢服务器出口 IP 已满足微信后台的 IP 白名单要求。正式使用时开启微信开发者工具的合法域名校验验证，不能用本地「不校验合法域名」代替后台设置。

## 构建和导入

在 frontend 目录执行：

```powershell
node --test tests/account-login.test.mjs
npm.cmd run build:mp-weixin
```

微信开发者工具导入 `frontend/dist/build/mp-weixin`。本机编译产物不等于已上传或已发布。

本地页面调试可指定 pages/account-confirm/index，查询参数为 scene=中枢当前生成的32位票据。无真实票据时会显示无效或过期，不模拟授权成功。H5/App 入口显示使用微信扫码的提示，不能作为微信确认渠道。

## 真实联调验收

1. 在业务站主动点击 52okp 登录，网页展示小程序码。
2. 微信扫码进入该 AI 小程序，页面显示正确申请应用；扫描本身不完成登录。
3. 未同意说明时确认被拦截；同意并点击确认后，原网页继续认证并完成登录。
4. 取消请求后原网页不能登录；过期和重复处理不能重新授权。
5. 绑定请求显示「确认绑定」，最终绑定结果在原网页核对。
6. 网络失败或响应异常不会显示成功；提交超时后先查看原网页结果。
7. 确认页返回教程首页，原有文章、收藏、历史和个人资料仍可使用。
8. 登录一个站后访问另一个站不会自动登录，后者仍由用户主动点击登录。

不同小程序 AppID 的微信身份不自动等同。既有统一账号先通过中枢绑定流程绑定这套小程序，避免误建另一账号。切换中枢配置的小程序后，在原网页刷新二维码再扫码。

账号说明页保留原项目的开发接入说明，并补充了教程会员与统一账号的边界。正式发布前由运营方补齐正式协议中的主体、联系方式和数据保留期限。
